Ten type systems, each on the same four jobs

A landing page asks type to do four different jobs, and most pairings are good at three of them. So every row below runs the same set: the eyebrow, the headline at band scale, a real body paragraph, and — the one that eliminates candidates — the spec readout, where measurements and the 217 → 4 count have to line up and stay legible.

What I'd
take

7c — Sora over Plus Jakarta Sans, with Space Grotesk kept for specs only. It is a small move from where you already are, it earns the precision claim the whole page is making, and it keeps the Indonesian body font doing the reading. Three faces sounds like a lot; in practice it is one for headlines, one for prose, one for numbers, and each one is doing a job the others can't.

Against it: Sora is wide, and it carries the same 3 → 4 line penalty I flagged as a liability on 7g. I'm not going to pretend that away. The difference is what the extra line costs — 7g's Unbounded is wide and a display face you can't use anywhere else, so the cost recurs at every heading size; Sora's is a measure problem, solved by writing a shorter headline or widening the band to 24ch. If you're not willing to touch the headline copy, take 7a instead — it is the only recommendation here that needs no copy changes at all.

If you want fewer moving parts, 7a is the honest minimum — one family, already self-hosted, nothing new to load, and the Jakarta provenance is real rather than decorative. If you want the page to look unlike any other parts platform, 7e is the one that does it, and I'd want to see it on the full page before committing.

One constraint worth naming: whatever you choose has to be self-hostable. Your repo already self-hosts Plus Jakarta Sans as a variable font rather than calling Google — keeping that pattern matters for load time in Indonesia and for not leaking visitor IPs to a third party. Every option here can be self-hosted; the ones marked already loaded cost nothing extra.
